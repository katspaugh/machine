# Nix Flake Packaging Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Nix flake so users can `nix profile install github:katspaugh/machine` / `nix run github:katspaugh/machine`, mirroring the Homebrew formula.

**Architecture:** A single `flake.nix` at the repo root with an inline `stdenv.mkDerivation` that installs the tree to `$out/libexec/machine`, wraps `bin/machine` with nixpkgs `python3` and `lima` on PATH, and installs shell completions. `scripts/release.sh` gains a pre-tag step that bumps the flake's version string. README and the docs site gain a Nix install subsection.

**Tech Stack:** Nix flakes, nixpkgs-unstable (`lima` 2.1.1, `python3`), bash, sed.

**Spec:** `docs/superpowers/specs/2026-06-03-nix-flake-design.md`

**Verification constraint:** Nix is NOT installed on the dev host. Tasks 1's flake can't be built locally — final verification (Task 4) happens on a machine with Nix after pushing the branch. Everything bash/sed-based is verified locally.

### Task 1: `flake.nix`

**Files:**
- Create: `flake.nix`

- [ ] **Step 1: Write `flake.nix`**

Create `flake.nix` at the repo root with exactly this content:

```nix
{
  description = "machine — one isolated Lima VM per project";

  inputs.nixpkgs.url = "github:NixOS/nixpkgs/nixpkgs-unstable";

  outputs =
    { self, nixpkgs }:
    let
      version = "0.2.0";
      systems = [
        "aarch64-darwin"
        "x86_64-darwin"
        "aarch64-linux"
        "x86_64-linux"
      ];
      lib = nixpkgs.lib;
      forAllSystems = f: lib.genAttrs systems (system: f nixpkgs.legacyPackages.${system});
    in
    {
      packages = forAllSystems (pkgs: rec {
        machine =
          # machine needs Lima >= 2.0 (template composition, `mode: data`
          # provisioning). Fail the build loudly if nixpkgs ever regresses.
          assert lib.assertMsg (lib.versionAtLeast pkgs.lima.version "2.0")
            "machine requires Lima >= 2.0, but nixpkgs has ${pkgs.lima.version}";
          pkgs.stdenv.mkDerivation {
            pname = "machine";
            inherit version;

            # Build from the flake's own source tree. `.git` is excluded from
            # flake sources, so the CLI's checkout detection stays false and
            # it uses XDG config/state dirs, same as under Homebrew.
            src = self;

            nativeBuildInputs = [
              pkgs.makeWrapper
              pkgs.installShellFiles
            ];

            dontBuild = true;
            doInstallCheck = true;

            installPhase = ''
              runHook preInstall

              mkdir -p $out/libexec/machine
              cp -R . $out/libexec/machine

              # Same shim as the Homebrew formula: pinned interpreter, Lima
              # on PATH. The script resolves templates/provision/files
              # relative to its own location under libexec.
              makeWrapper ${pkgs.python3}/bin/python3 $out/bin/machine \
                --add-flags "$out/libexec/machine/bin/machine" \
                --prefix PATH : ${pkgs.lima}/bin

              installShellCompletion --cmd machine \
                --bash completions/machine.bash \
                --zsh completions/_machine \
                --fish completions/machine.fish

              runHook postInstall
            '';

            # Mirrors the formula's `test do` block.
            installCheckPhase = ''
              runHook preInstallCheck
              $out/bin/machine --help | grep -q machine
              $out/bin/machine --help | grep -q init
              runHook postInstallCheck
            '';

            meta = {
              description = "One isolated Lima VM per project — Docker, Node, agent CLIs, signed git";
              homepage = "https://runmachine.dev";
              license = lib.licenses.mit;
              mainProgram = "machine";
              platforms = systems;
            };
          };
        default = machine;
      });

      apps = forAllSystems (pkgs: {
        default = {
          type = "app";
          program = lib.getExe self.packages.${pkgs.stdenv.hostPlatform.system}.default;
        };
      });
    };
}
```

### Task 2: Flake version bump in `scripts/release.sh`

**Files:**
- Modify: `scripts/release.sh:5-12` (header comment) and `scripts/release.sh:34-38` (insert before the tag step)

The formula bump must stay *after* tagging (it pins the tag tarball's sha256), but the flake builds from `self`, so the tagged commit must already carry the new version. Insert the flake bump immediately *before* "1. Tag + push".

#   1. Tags vX.Y.Z in this repo and pushes the tag.

#   3. Rewrites url + sha256 in this repo's Formula/machine.rb, commits, pushes main.

#      flake builds from its own source tree).
#   2. Tags vX.Y.Z in this repo and pushes the tag.
#   3. Downloads the tagged tarball from GitHub, computes its sha256.
#   4. Rewrites url + sha256 in this repo's Formula/machine.rb, commits, pushes main.
#   5. Clones katspaugh/homebrew-machine, mirrors the formula, commits, pushes.
#   6. Creates a GitHub Release with auto-generated notes.

- [ ] **Step 2: Insert the flake bump step**

In `scripts/release.sh`, replace:

```bash
# 1. Tag + push
echo "==> tagging $TAG"
```

with:

```bash
# 1. Bump flake.nix version — must land before the tag so the tagged
#    commit builds with the right version (the flake's src is `self`).
if grep -q "version = \"$VERSION\";" flake.nix; then
  echo "==> flake.nix already at $VERSION"
else
  echo "==> updating flake.nix version to $VERSION"
  sed -i.bak -E \
    "s|^([[:space:]]*version = \")[0-9]+\\.[0-9]+\\.[0-9]+(\";)|\\1$VERSION\\2|" \
    flake.nix
  rm -f flake.nix.bak
  git add flake.nix
  git commit -m "Bump flake version to $TAG"
fi

# 2. Tag + push
echo "==> tagging $TAG"
```

Then renumber the remaining step comments in the same file:
- `# 2. Compute tarball sha256` → `# 3. Compute tarball sha256`
- `# 3. Bump this repo's reference formula` → `# 4. Bump this repo's reference formula`
- `# 4. Mirror into the tap` → `# 5. Mirror into the tap`
- `# 5. GitHub Release with auto notes` → `# 6. GitHub Release with auto notes`
